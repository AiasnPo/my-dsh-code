# dsh-ctx-meter

看清一个 [DeepSeek Harness](https://github.com/deepseek-ai) 会话到底吃掉了多少上下文：**每次请求的真实 token、压缩发生了几次、当前预算花在哪些记录上**——全部读自 DSH 自己落盘的会话日志，不猜、不估算。

顺带解决另一半问题：**三个月前那些聊过、后来再没提过的会话去哪了**。`--stale` 会把它们找出来，判断之后是否又被引用，并把**原文与摘要分开归档**：越老、越没人提，摘要越短。

零第三方依赖，纯 Node，直接读磁盘。

## 为什么需要它

DSH 的 `usage` 字段只对**当次请求**负责。一个长会话里，历史被反复重发，真实成本要一句一句加起来看。压缩（compaction）又把请求视图换了一次，于是「我以为只用了 20%」和实际水位之间会差出几十个百分点。

`dsh-ctx` 把这件事拆开算清：

| 数字 | 是什么 | 从哪来 |
| --- | --- | --- |
| 上下文占用 | 最近一次请求实际发出去的输入与输出 | `request/context` + `usage` |
| token 账单 | 全会话逐条 `usage` 累加的真实消耗 | 每条 `assistant/message.usage` |
| 压缩挤出量 | 每次压缩从上下文里移走了多少 | `compaction/summary` 前后的记录序列 |
| 压缩自身消耗 | 为压缩额外付的 prompt + 输出 token | 压缩请求自己的 `usage` |

## 安装

```bash
npm i -g dsh-ctx-meter      # 或者：npx dsh-ctx-meter
```

手动运行（本仓库）：

```bash
node bin/dsh-ctx.js          # 最新会话的完整报告
node bin/dsh-ctx.js --help   # 全部选项
```

要求 Node **>= 22.15**（需要 `zlib.zstdDecompressSync` 解开 `.zstd` 会话日志）。

## 用法

```bash
dsh-ctx                              # 最新会话的完整报告
dsh-ctx --list                       # 列出所有会话
dsh-ctx -s 443c60eb                  # 按 id 前缀挑选
dsh-ctx --json | jq '.current'       # 机器可读，接自己的看板
dsh-ctx --fail-if-over 80            # 占用过 80% 退出码 3，便于脚本告警
```

会话根目录自动探测：`$DSH_SESSIONS_DIR` → `$DSH_PROFILE_DIR/sessions` → `$DSH_HOME/sessions` → `~/.dsh/sessions`。也可用 `--root` 显式指定。

## 陈旧内容检测（`--stale`）

```bash
dsh-ctx --stale                      # 归档超过 30 天的会话
dsh-ctx --stale --days 60 --dry-run  # 只看 60 天以上，不写盘
```

### 三个判断，各自独立

1. **多老**——按距今天数分四档，摘要字符预算逐档收紧；
2. **后来还被提到吗**——从旧会话抽关键词（路径/文件名权重最高），到「比它更新的会话」里找命中；命中够多就认为它还被惦记着，**预算放宽**；
3. **怎么存**——原文、摘要、索引三处分开，索引里只有指针。

### 分档

倍数相对归档门槛 `--days`（默认 30 天），所以改门槛后表格不会自相矛盾：

| 档位 | 门槛 30 天时 | 未被提及 | 已被提及 |
| --- | --- | --- | --- |
| 新鲜 fresh | < 30 天 | 不归档 | 不归档 |
| 渐远 aging | 30–90 天 | 160 字符 | 320 字符 |
| 陈旧 stale | 90–180 天 | 90 字符 | 200 字符 |
| 沉睡 dormant | ≥ 180 天 | 45 字符 | 110 字符 |

一句话：**没人再提的老会话，只留一句摘要 + 一个原文指针；还在被提的，多留几倍。**

### 归档目录

```
dsh-ctx-archive/
├── index.json               # 查询面：指针 / 天数 / 分档 / 是否被引用 / 关键词 / 哈希
├── raw/<会话id>.txt         # 原文完整转录（人可读，不是 JSON dump）
└── summaries/<会话id>.md    # 摘要与判据，明确写「是否被后续提到」「预算多少、为什么」
```

`index.json` 刻意压成单行紧凑 JSON，只存指针与判据，**不夹带任何正文**——想读内容就去对应文件，或者直接用 `rawHash` 校验原文没被动过。

## 真正释放空间：`--purge` 与 `--slim`

`--stale` 只是**搬家**，磁盘占用一分没少。要减负，得自己决定删还是瘦：

```bash
dsh-ctx --purge                      # 预览：哪些老会话会被归档后删掉
dsh-ctx --purge --days 90 --yes      # 先归档，确认完整，再删掉 90 天以上的会话目录
dsh-ctx --slim                       # 预览：老会话能裁掉多少字符
dsh-ctx --slim --min-age 30 --yes    # 真给老会话瘦身（默认留 .bak）
```

两者**一次只能用其一**，也**默认只预览**，不加 `--yes` 绝不写盘。

### `--purge`：删，但先证明可以删

顺序不可颠倒——**先归档，再删**。只有同时满足「`index.json` 里有该条目」「`raw/` 文件存在且非空」「该条目没有 `error`」的会话才会被删除，任何一步存疑就跳过并报原因（`not-archived`）。删除动作追加进 `<archiveDir>/purged.jsonl`，随时可查谁在什么时候被删。

安全闸：目录名必须匹配 `session-*`，否则当没看见；删空一个工作区目录后顺手清掉空的父目录。

### `--slim`：不删记录，只裁大块文本

就地重写会话文件，只动两类内容，且只在字面量远超阅读所需时才动：

| 对象 | 默认阈值 | 保留 |
| --- | --- | --- |
| `tool/result` 里的 `text` | > 4000 字符 | 头 2400 + 尾 1200 |
| `assistant/message` 里的 `reasoning` | > 2000 字符 | 头 1200 + 尾 400 |
| `tool/call` 的 `arguments` | 默认**不动**（命令行不暴露开关；库里传 `slimToolCalls: true` 才开） | 头 2000 + 尾 300 |

**用户消息、assistant 的正式回复、压缩摘要、`request/header`（工具定义快照）一律不碰**——它们是回看历史时真正要读的东西。被裁的位置留一句 `…（已瘦身：省略 N 字符）…`，读到时候不至于误以为内容丢了。

三道闸保证不写坏文件：① 不删任何一条记录，只改 `text` 值；② 写临时文件后**重新解压校验**记录数、`seq` 序列、逐条可解析；③ 覆盖前默认留 `<会话文件>.bak`。任一步不符就放弃该会话，不碰原文件。瘦身结果追加进 `<archiveDir>/slim.jsonl`。

会话文件是**多帧 zstd**（按魔数 `28 b5 2f fd` 首尾相接），所以重写时也要按行切块、逐帧压缩再拼接，否则读取端只能解出第一帧。

## 设计取舍

- **纯规则，不调 AI。** 摘要用「首句定主题 + 关键词密度挑句 + 预算截断」，可复现、可测试、零成本。要更聪明的摘要，自己接模型。
- **先过滤系统样板。** 会话开头常是英文系统提示与工具清单，它们比对话更像「重点」，所以显式降权——否则摘要第一句永远是 `You are an AI assistant…`。
- **宽容读记录。** 记录结构随版本会变，取文本只认常见键，跳过 base64 内联资源与超长单串。
- **说清局限。** 引用检测是词面匹配，同义改写会被漏判；被判成「没再提过」只意味着**字面上**没再提过。

## 开发

```bash
npm test        # 三个套件顺序跑：stale → purge → slim（共 26 条断言）
npm run check   # 对 bin 与 src 全部文件做 node --check
```

测试自带极简 runner，直接 `node tests/slim.test.js` 也能单独跑。**沙箱里别用 `node --test tests/`**——它需要管道捕获子进程输出，会被拦成 `spawn EPERM`；而 `node --test` 本身也没必要。

测试会真的写盘，所以全部落在 `fs.mkdtemp` 出来的临时目录里，跑完即删，不碰你的真实会话。

另外两个测试上的坑，改测试前先知道：

- **zstd 会把重复内容压掉。** 想造「多帧」样本，测试数据必须不可压缩——用 `Math.imul` 做 32 位伪随机；体积断言也别写「变小了」，直接断言 `decoded.frames > 1`。
- **会话文件是多帧的。** 直接 `zstdDecompressSync` 整个缓冲区只解第一帧，`store.js` 是按魔数切片逐帧解的。
